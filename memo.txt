ロジェクト概要

フリックIME — Android用の日本語フリック入力キーボード（InputMethodService）。Windowsの Win+V（クリップボード履歴）と Ctrl+Z/Ctrl+Y（元に戻す・やり直し）に相当する機能を、キーボード上のツールバーに載せたもの。

なぜIMEとして作ったか — Androidにはこれらのシステム全体機能が存在せず、かつ Android 10 (API 29) 以降はフォアグラウンドのアプリと既定のIMEしかクリップボードを読めない。IMEとして実装することが、「どのアプリの上でも使える」を満たす唯一の現実的な経路でした。

設計上の要点：undoは「このIMEがInputConnection経由で行った編集」のみを対象とし、実行前にカーソル直前のテキストを照合します。他所で変更されていたら履歴を破棄する — 誤った文字を消さないためです。カーソル位置をexpectedCursorで追跡し、自分の編集か外部からの変更かを判別しています。

現状のステータス

⚠️ コンパイル未検証。この環境にJDK・Android SDK・Gradleが無いため、書いたKotlinは一度もビルドを通していません。型エラーやリソース参照ミスが残っている前提で見てください。

ネクストステップ（優先順）

1. ビルド環境の構築 → コンパイルを通す ← 最優先
他のすべてがここでブロックされています。winget install Google.AndroidStudio が確実（SDK・エミュレータ・Gradle Wrapper が一括で揃う）。軽く済ませるなら OpenJDK 17 + commandline-tools。

2. 実機/エミュレータでの挙動調整
フリック閾値（既定22dp）とキー高さは設定画面から変えられるようにしてあるので、実際に触って詰める段階です。

3. 既知の穴を塞ぐ
- 機微なコピーの除外 — Android 13以降、パスワードマネージャ等は ClipDescription.EXTRA_IS_SENSITIVE を立てます。現在これを見ておらず、パスワードが履歴に残ります。プライバシー上ここは先に直すべきです
- 選択範囲の削除・複数行での undo 照合の検証
- 長押しリピート削除時の履歴マージ挙動の確認

4. 単体テスト — KanaModifier と EditHistory は Android 実機なしの JVM テストで検証できます。ビルド環境さえ入れば、InputConnection をフェイクにして undo/redo の正当性を固められる。費用対効果が最も高い部分です。

5. 機能拡張（工数順）
カタカナ/英数変換キー → キーボード高さのIME上調整 → 片手モード → かな漢字変換（Mozc等の組み込み。ここだけ桁違いに重く、setComposingText による未確定文字列管理の追加が必要）
